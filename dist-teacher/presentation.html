FIREWALLS & TRAFFIC

Why Control Traffic In and Out?

You only want traffic to enter or leave your server that actually needs to. A firewall lets you control inbound (ingress) and outbound (egress) traffic — the same least-privilege principle you'd apply to IAM permissions.

Open only what's needed
A web server usually needs just port 80 (HTTP) and 443 (HTTPS) open. Everything else stays closed.
Fewer holes, less risk
A strict firewall shuts down a lot of possible security holes before they become a problem.
Prevent accidents too
Not opening outbound SMTP on a test system stops it from accidentally emailing real customers.

FIREWALLS & TRAFFIC

Inbound vs. Outbound Traffic

Inbound (Ingress)
Traffic coming into your server from somewhere else — like a visitor's browser requesting your website.
Outbound (Egress)
Traffic leaving your server — like your server calling out to an API, sending mail, or pulling updates.
📌 Before traffic can enter or leave your instance, it passes through a firewall that inspects it and applies your rules.

SECURITY GROUPS

The Default Behavior

Inbound: Denied by default
Nothing can reach your server until you explicitly add a rule allowing it in.
Outbound: Allowed by default
Your server can reach out anywhere — until the moment you add your first outbound rule.
⚠️ The switch to watch for
The moment you add any outbound rule, the default flips from “allow all” to “deny all” — only the exceptions you've explicitly added stay allowed.

SECURITY GROUPS

What a Security Group Rule Can Match

A security group is a set of rules attached to your AWS resources (like EC2 instances). Each rule can filter on:

Direction
Inbound or outbound
IP Protocol
TCP, UDP, or ICMP
IP Range
Specific address or CIDR range
Port
e.g. 22 for SSH, 443 for HTTPS
Sec Group
Another security group (AWS-only)
Good practice: define rules as restrictive as possible. AWS won't stop you from allowing everything — but you should.
Security Groups Slide 6 of 13
SECURITY GROUPS

Source vs. Destination: Which Way Rules Filter

Inbound rules filter by SOURCE
Where is this traffic coming from? You allow inbound traffic only from specific source IP ranges — or specific security groups.
Outbound rules filter by DESTINATION
Where is this traffic going? You allow outbound traffic only to specific destination IP ranges — or specific security groups.
💡 AWS is responsible for the firewall itself — you're responsible for the rules you write.

Why Reference a Security Group Instead of an IP?

Cloud servers come and go — rules based on fixed source IP addresses get out of date fast. Referencing a security group instead stays correct automatically.

BASTION HOST PATTERN

The Problem: Too Many Doors

The Risk of Direct Access
If every server allows SSH directly from the internet, you have many possible entry points to defend — and if any one server is compromised, an attacker may be able to jump to the others.
The Fix: A Bastion Host (Jump Box)
Only one server — the bastion host — can be reached via SSH from the internet, ideally restricted to a specific source IP. Every other server can only be reached via SSH from the bastion host itself.
Bastion Host Pattern Slide 9 of 13
BASTION HOST PATTERN

Implementing It: Two Rules

1
Allow SSH to the bastion host
From 0.0.0.0/0, or better, a specific known source IP address.
2
Allow SSH to every other server — but only from the bastion
The source for this rule is the bastion host's security group, not the open internet.

BASTION HOST PATTERN

Why This Pattern Works

One entry point, one job
You have a single entry point into your system, and that entry point does nothing but SSH. The chances of it being compromised are small.
No lateral movement
If a web server, mail server, or FTP server is hacked, the attacker can't jump from that server to all the others.

SUMMARY

Key Takeaways

🛡️
Open only the ports you need — typically 80/443 for a web server — and close everything else.
🔒
Inbound traffic is denied by default; outbound is allowed by default until you add a rule.
⚡
Reference security groups instead of fixed IPs so rules stay correct as servers change.
🏰
A bastion host gives you one controlled entry point and stops attackers from moving laterally.
